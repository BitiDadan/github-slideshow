# 财务科目对照导入工具 v1.6.0

C# / WinForms / .NET Framework 4.8。读取 Excel 科目对照表，预览后生成 SQL Server 2014 兼容的 INSERT 脚本，或导出一个含两个工作表的 Excel 报告。不依赖安装 Office。完全离线运行。Excel报告导出会读取所选源Excel同目录下的“当前主数据.xlsx”作为客户/供应商类型参照，不连接数据库。

## 下载运行

打开本目录 `Downloads/FinanceMappingTool-v1.6.0.zip`，点击 GitHub 的 **Download raw file** 下载完整包。完整解压后进入 `Program`，双击 `FinanceMappingTool.exe`。EXE、DLL、配置文件必须放在同一目录。

需要 Windows 和 .NET Framework 4.8。无需安装 Python、.NET 8 或 VS 即可运行。

## VS 2022 编译

安装“.NET 桌面开发”工作负载及 .NET Framework 4.8 开发包；打开 `Source/FinanceMappingTool.sln`，还原 NuGet 后以 Release 编译。

## 使用步骤

1. 选择 `.xlsx`，默认工作表“科目对照表”，表头第1行。
2. 若表头名称有缺失、改名或重复，会弹出字段对应窗口：先选择左侧所需字段，再勾选右侧来源列，五个字段全部对应后确认读取。可通过列字母及示例值区分重名/空表头。取消则不导入，也不保留旧文件的可导出数据。
3. 预览结果及日志，可以修改科目编码、名称和属性。
4. 第二行填写公司编码、公司名称、币制（默认VND）；映射类型文本框填写基础名称，默认KDVoucher。主账簿最终映射类型为“基础名称＋币制”，并在UI和预览中显示；副账簿类型在其后追加02。填写实际目标数据库名称。目标数据库默认值为 `Settlesnap`，可按部署环境修改。
5. 导出 SQL，先在测试数据库用 SSMS 打开并核对执行。已取消跨OverseasType比较FeeNoOverseas的前置检查，不再生成该比较过程或人工确认开关。原有同一目标类型下的重复/完整内容冲突保护仍然保留。
6. 或将自己的“当前主数据.xlsx”放到本次选择的源Excel文件同目录下，再点击“导出 Excel”，选择一个.xlsx文件保存位置。程序读取参照文件的Main工作表，完成检查后生成一个Excel文件。

所需字段：`*编码`（海外科目编码）、`名称（越南文）`（海外科目名称）、`科目编码`（国内科目编码）、`科目名称`（国内科目名称）、`科目类型`。不再固定A/C/D/E/F位置：五个名称各自唯一存在时按名称自动匹配，即使列顺序改变也能读取。

表头改名、缺失或重名时要求人工确认对应关系；每个所需字段选一个来源列，不允许多个所需字段共用同一来源列。表头与数据读取使用同一份内存工作簿，避免选择后文件变化导致错位。本版每次导入重新匹配，不保存模板对应关系。工作表名、单行表头所在行仍在主界面填写，不自动识别多行/合并表头。

日志会列出五个字段最终采用的Excel列。预览表格列头高度增加约50%，在当前DPI下计算并允许标题换行。
两侧均空忽略；缺一侧编码跳过并记录；空名称保留并提示；同一国内编码默认取第一条并列出重复行。

## 公司信息与公司关系SQL（v1.4.0）

界面第二行从左到右为“公司编码”“公司名称”“币制”和“账套编码去除前导零”勾选框，币制默认VND，勾选框默认勾选。原“映射类型”文本框只输入基础名称，UI最终类型为“基础映射类型＋币制”，不插入分隔符；副账簿在该值后追加02。公司编码为空时跳过公司关系和公司本币，仍生成两账簿的其余SQL，币制始终必填。

公司编码框支持粘贴“[数字编码]公司名称”，例如[000123]DEMO ANZ PTY LTD。输入完成离开该框或按回车时，自动将方括号内数字文本填回公司编码、方括号外文本填入公司名称（替换原公司名称）；编码不转数字，完整保留前导零，支持名称含中文及数字。不符合单组方括号数字格式的内容不自动拆分。临时输入框可接收完整信息，拆分后的公司编码仍按17字符上限及原有字段规则校验；导出SQL前也会尝试拆分。

公司编码非空时，在同一SQL文件中增加VoucherCompanyRelation导入：

| SQL字段 | 来源 |
| --- | --- |
| CompanyCode | 公司编码，保留前导零 |
| AccountType | 受“账套编码去除前导零”控制：默认勾选时去除前导零，取消勾选时保留原编码，再分别追加@01、@02；勾选时全零编码保留一个0 |
| OverseasType | @01使用基础映射类型＋币制；@02使用基础映射类型＋币制＋02。公司、凭证类型、辅助核算/现金流及科目共同采用此规则 |
| LanguageType | 主账簿@01使用UI币制；副账簿@02固定为CNY（人民币） |
| Memo | [公司编码]公司名称，使用Unicode字面量 |
| IsRoundOff | 固定0 |

默认勾选时，例如虚构编码000123、基础类型DemoType、币制AUD：公司账套123@01对应DemoTypeAUD，123@02对应DemoTypeAUD02（CompanyCode及Memo中的编码仍为000123）；主账簿科目/凭证类型使用DemoTypeAUD，副账簿使用DemoTypeAUD02。输入基础类型时不要预先追加币制，否则会再次拼接。 两条公司关系的CompanyCode、Memo和IsRoundOff相同；LanguageType在@01使用UI币制，在@02固定CNY；AccountType分别是@01和@02，OverseasType分别采用“基础映射类型＋币制”和“基础映射类型＋币制＋02”；两条都在“凭证公司”区块内，先@01后@02，之后是两账簿18条凭证类型、内置现金流/摘要SQL和科目。存在性及重复检查分别按账套进行，有效的@01和@02各一条不视为重复；“公司关系新增条数”累计实际新增的两条。

凭证公司、公司本币、凭证类型、现金流/摘要和科目关系在同一个事务内执行；公司编码＋账套的有效关系已存在且内容相同则跳过，存在多条或内容不同则报错整体回滚，不自动覆盖。CreateDate和IsDeleted使用提供的表默认值。目标库需存在VoucherCompanyRelation和BaseCurrencyDefine（公司编码非空时）、VoucherTypeRelation、VoucherAuxiliaryRelation、VoucherAbstractRelation和VoucherFeeRelation。

AccountType示例：公司编码090102，勾选“账套编码去除前导零”时生成90102@01、90102@02；取消勾选时生成090102@01、090102@02。此选项只影响AccountType，CompanyCode及Memo保持UI原公司编码；已有关系的查询和校验也跟随此选项。切换勾选状态不重置科目预览。

长度限制遵循表结构：AccountType最长20字符，因此公司编码最多17字符；科目最终映射类型最多50字符，公司映射类型（含币制及02后缀）也最多50字符；[公司编码]公司名称合计最多400个UTF-16字符。编码、基础类型和币制使用可打印ASCII字符，公司名称支持中文等Unicode。无论公司编码是否为空，币制都不能为空；主账簿最终类型最多48字符，以预留副账簿02后缀。

预览及Excel报告只显示主账簿，内容与当前预览保持一致。SQL导出会复制一套副账簿科目，将OverseasType改为主账簿类型＋02，并将海外科目编码FeeNoOverseas替换为同一行国内科目编码FeeNo，保留其前导零。此替换只用于副账簿SQL，海外科目名称FeeNameOverseas及其他属性保留预览值；主账簿SQL、当前预览和导出Excel保持原海外科目编码及手工修改。参照主数据的异常检查规则不变。

## 凭证类型及SQL顺序（v1.4.1）

生成的SQL按以下注释区块从上到下排列，凭证公司和凭证类型的业务插入也在科目暂存数据之前：

1. `-- 凭证公司`：生成VoucherCompanyRelation语句；公司编码为空则保留注释并跳过此表。
2. `-- 公司本币`：UI公司编码非空时，对BaseCurrencyDefine按CompanyCode判断是否存在；不存在才插入。CompanyCode保留UI编码前导零，BaseCurrencyNo取UI币制，CreateDate为GETDATE()，NCCAccountType为''。只生成一个公司本币区块，不额外生成副账簿CNY记录；已有数据直接跳过，不覆盖。
3. `-- 凭证类型`：主、副账簿分别按OverseasType判断是否已存在；不存在时各插入9条VoucherTypeRelation，最多18条，固定依次为A、B、C、D、E、F、G、H、01。NCCVoucherType和OverseasVoucherType取同一个字符串，Memo为''。01始终带引号，保留前导零。
4. 内置“现金流”和“凭证摘要”区块：根据提供的模板生成。
5. `-- 科目`：按主、副账簿暂存并检查科目数据，再插入VoucherFeeRelation。N条主账簿预览会生成2N条待导入科目。

主、副账簿分别使用UI最终映射类型和该值＋02，所有业务表对应一致。副账簿涉及的币制固定为CNY，但OverseasType仍为主账簿最终映射类型＋02，例如KDVoucherAUD02；公司关系的已有数据校验也按各自账簿的币制进行。公司编码为空时仍生成两套凭证类型、现金流及科目。所有区块在同一事务内执行并共同提交或回滚。

凭证类型、现金流和凭证摘要各自在对应表中，仅按OverseasType判断是否存在相同类型（不增加CompanyCode、IsDeleted或单项编码条件）。该表已有任意一条该类型记录，就跳过本次这一整组，既不补齐缺少项，也不修改已有内容；主、副账簿分别判断，各表互不影响，后续科目仍继续处理。凭证类型每组9条，辅助核算/现金流每组9条，主账簿摘要一组3条。不存在时仍使用固定INSERT VALUES，凭证类型两个编码相同且Memo为''。存在性查询使用UPDLOCK/HOLDLOCK并沿用现有事务及锁等待超时。公司及科目部分原有的校验规则保持不变。

执行成功后的结果集增加“凭证类型跳过条数”“现金流新增条数”“现金流跳过条数”“凭证摘要新增条数”“凭证摘要跳过条数”，保留“凭证类型新增条数”及原有科目/公司统计。跳过数指本次因类型存在而未执行的计划插入条数，不是库中已有记录数量。例如只存在一条主账簿凭证类型，也会计为本次跳过9条。

## 内置现金流与凭证摘要（v1.6.0）

提供的SQL模板已嵌入程序，在凭证类型之后、科目之前输出：主账簿9条VoucherAuxiliaryRelation、副账簿9条，以及主账簿3条VoucherAbstractRelation，共21条INSERT。保留模板“副账簿默认CNY无需配置”的摘要说明，不额外生成副账簿摘要。

只替换模板中OverseasType列：原KDVoucherAUD→UI最终映射类型，原KDVoucherAUD02→UI最终映射类型＋02；主账簿凭证摘要的LanguageType同步使用UI币制；副账簿仍按模板说明使用CNY且不额外生成摘要。“付运费”的英文摘要统一为小写pay freight；生成时仅对TranslateAuxiliary的英文内容补上末尾一个半角空格，已有末尾空格则不重复添加，中文、空值及纯数字不添加；主账簿AuxiliaryCode=0007的AuxiliaryJsonOverseas采用新CFI-IFRS映射，其中112410/112413/112414分别映射01.02.04.08/11/12；副账簿对应行保留原CI映射。其余字段及AuxiliaryJsonOverseas字符串按原文保留，不进行JSON转换。模板中的全角语句分隔空格转换为普通空格。

模板以Source/cash-flow-template.sql嵌入EXE，运行时不需要复制单独的模板文件。现金流及摘要的INSERT字段内容按模板保留，外层新增按表和OverseasType跳过整组的判断与新增/跳过计数。SQL Server语法校验仅检查SQL结构，不代表已验证业务系统对模板数据的解释。

## Excel导出与异常检查（v1.3.1）

只导出一个.xlsx文件，必定包含且仅包含以下两个sheet，顺序固定：

1. **科目数据**：直接取当前预览快照；列头、列顺序和单元格值保持一致，包含预览中的手工修改。编码按文本保存，保留前导零。
2. **异常科目**：左侧先增加“异常数据行号”“异常说明”，后面接全部预览列头及对应数据。没有异常时仍保留此sheet及全部列头。

“异常数据行号”指科目数据sheet中的实际Excel行号（包含第1行表头），便于直接定位；原始上传Excel行号仍保留在原“Excel行”列。同一数据行命中两项检查，会分别列出两条记录，说明文字分别为：

- `海外科目名称为空`：FeeNameOverseas为NULL、空字符串或仅包含空白字符。
- `客户\供应商类型异常`：以相同FeeNo匹配有效KDVoucher参照，比较CustomerType数值（1客户，2供应商），不同则列出。不比较FeeNoOverseas。参照缺少此FeeNo不作为类型异常；参照CustomerType为NULL或同编码多条参照中任一类型与当前值不一致，也会列为类型异常。

参照文件固定为本次选择的源Excel文件同目录下的 `当前主数据.xlsx`，工作表固定为 `Main`；首个非空行作为列头，按列名查找 `FeeNo` 和 `CustomerType`（忽略列名两侧空白及大小写），列顺序不限。CustomerType支持数值/文本的1和2，空值保留为未知类型；非法值或重复必要列名会报错。FeeNo按文本或显示格式读取，保留已有前导零。

若还包含 `OverseasType` 列，只取KDVoucher；若还包含 `IsDeleted` 列，只取值为0的行。没有这两个可选列时，视为已整理好的参照主数据。空FeeNo行忽略。同一FeeNo多条参照中存在不同类型时，仍按已有异常规则标记。

将待解析的源报表和 `当前主数据.xlsx` 放在同一文件夹即可。例如选择 `D:\报表\待导入.xlsx` 时，参照路径为 `D:\报表\当前主数据.xlsx`。更换源报表目录后，参照目录会同步更换；导出保存目录和程序安装目录不影响参照路径。已移除编译时复制主数据到输出目录的设置。交付包和公开仓库均不包含实际主数据。

文件缺失、Main工作表缺失或必要列头缺失时，会提示具体问题并停止Excel导出，不会跳过参照检查生成不完整报告。读取成功但有效参照为0时，仍检查名称空白，并在日志提示没有可进行类型比对的国内科目。文件路径、读取时间和条数只写日志，不额外增加sheet。

不会覆盖或修改参照文件，也不允许把报告保存为正在读取的参照文件同一路径。

报告检查针对导出时的预览快照；SQL仍生成正常INSERT，不将这些异常检查或跨类型比较写入SQL，也不修改数据库。

预览第一列宽度在按内容计算的基础上增加约50%，绑定数据后也保留。

## 业务配置

此公开交付包不包含用户上传的 Excel、原 SQL、实际科目映射、业务修订配置或基于原数据生成的脚本。`mapping-rules.xml` 为通用空配置。
需要修订时，在运行目录配置并重新读取 Excel：

```xml
<MappingRules>
  <Override enabled="true" sourceFeeNo="DEMO01" sourceOverseas="DEMO02" feeNo="DEMO03" />
  <Type02Override feeNo="DEMO03" overseas="DEMO04" />
</MappingRules>
```

示例为虚构编码。Override 在去重前应用；Type02Override 用于02类型已存在的国内编码，不会自动新增科目。

## v1.1.1 LOCK_TIMEOUT 语法修正

v1.1 的两处 `SET LOCK_TIMEOUT @previousLockTimeout` 会被 SQL Server 引擎报语法错误102。之前ScriptDom解析通过并不代表引擎可以接受这种参数形式；已增加针对该问题的回归检查。

现在只输出常量形式：当原设置为无限等待（-1）时临时设置10000毫秒，成功或可捕获错误后用常量-1恢复。会话原本已有有限超时（包括0）时直接沿用，不修改该设置。消息中显示实际采用的毫秒值。旧文件需重新生成；如临时手工修改旧文件，在原会话超时为默认-1的前提下，将两处 `SET LOCK_TIMEOUT @previousLockTimeout;` 改成 `SET LOCK_TIMEOUT -1;`。

## 批量处理与锁等待

旧版每条映射会三次查询目标表并持有 UPDLOCK/HOLDLOCK；没有业务索引时可能反复扫描并持有更大范围的锁。单条映射也可能因其他未提交事务而阻塞，这需要实际会话信息确认，不能仅从耗时确定原因。

新版先将输入放入表变量，再用一条目标表读取语句缓存相关映射，批量校验和插入。仍保留事务与一致性锁，遇到其他会话持锁时仍可能等待；默认无限等待会话临时设置为10秒；原本已有有限超时则沿用，报1222后回滚并提示诊断。它不是整个脚本的总执行时限，回滚也可能需要时间。执行计划仍由数据库优化器决定，不保证物理上只扫描一次。

新增：
- 立即显示导入SPID及处理阶段，便于在另一窗口查看阻塞。
- 检查当前窗口是否已有未结束事务，有则拒绝开始；不会自动回滚用户原有事务。
- 成功和可捕获错误均恢复本脚本改动的LOCK_TIMEOUT、XACT_ABORT设置。
- 根据实际暂存输入动态统计条数，手工裁剪数据后不会仍显示原始总数。
- 支持超过1000条的VALUES分批暂存。
- `Diagnostics/检查导入阻塞.sql` 为只读诊断，不修改表、不KILL会话。

客户端点击停止不保证进入 SQL CATCH。停止后应在原窗口检查 `SELECT @@SPID,@@TRANCOUNT,XACT_STATE();`。若有事务，先确认属于哪项操作，再决定提交或回滚。不要用NOLOCK绕过导入一致性检查。

若LCK_M_*等待、blocking_session_id>0，说明在等待其他会话。先处理阻塞会话，不要自动结束其他人的事务。若目标表数据较大，可由DBA评估 (OverseasType,FeeNo,IsDeleted) 索引；本版不自动创建索引或修改表结构。

## 部署行为

- 按 OverseasType + FeeNo + IsDeleted=0 查找有效记录。
- 内容完全相同跳过；内容冲突或目标已有重复有效记录时报错，整个事务回滚。
- 不清空、不删除、不覆盖现有记录。已软删除记录不阻止新增有效记录。
- ID自增；CreateDate、IsDeleted依赖表的默认约束。
- Unicode字符串及单引号转义；文件编码UTF-8 BOM；兼容 SQL Server 2014。
- 表结构必须与工具列名、字段类型及默认值一致。当前版本不创建表结构。
- 编码建议Excel存为文本；已有前导零显示格式会保留，已丢失的前导零/精度无法恢复。
- 切换映射类型或重新读取会重置预览中的手工修改。

已完成Release编译，以及列顺序变化、表头改名、重名/空表头、人工指定、重复来源禁止、前导零格式、读取快照一致性、按选定字段校验编码等自动检查；原始Excel仍生成305条映射。另完成1条、305条、1001条及原始Excel生成脚本的SQL Server 2014语法解析检查。未在Windows实际启动界面，未连接用户SQL Server；隔离测试服务器因验证环境磁盘限制未能启动，因此未完成数据库运行及阻塞超时实测。Excel导出已用合成数据实际生成并重新打开验证：两个sheet名称顺序、所有数据单元格一致、空异常表保留、两类异常及同一行多异常、文本前导零、公式样式文本、覆盖保存。文件参照读取已覆盖列顺序/大小写/空白行、数值显示格式、可选过滤列、缺少文件或工作表、缺少/重名列及非法类型等验证。数据库连接代码和连接窗口已移除。

## 设置客户/供应商特例

点击主界面“设置特例”，弹窗中输入国内科目编码并选择1（客户）或2（供应商）。支持新增/更新、删除选中、保存并应用、取消。输入后可直接保存，或先点击新增/更新；取消不写入配置。编码按完整文本精确匹配，保留前导零，不按前缀匹配。

默认规则如下，可在弹窗修改或删除：

| CustomerType | 默认国内科目编码 |
| --- | --- |
| 1（客户） | 2203、220301、220399 |
| 2（供应商） | 1123、112301、112302、11230399、112398、6401、640101 |

规则保存在程序目录mapping-rules.xml的CustomerTypeExceptions节点。保存时保留Override和Type02Override等其他配置，保存失败不应用新规则。保存成功后同步当前预览，保留无关科目的手工修改和其他字段；删除某条规则时恢复该科目的原始科目类型/导入修订结果。下次启动继续读取保存的配置。

旧配置缺少CustomerTypeExceptions节点时使用上述10条默认规则；显式保存空节点表示已删除全部特例，之后只按常规科目类型和导入修订处理。公司编码、AccountType及CreditDebitType的原有规则不受此弹窗影响。
